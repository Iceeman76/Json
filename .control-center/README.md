## One-time repository setup

Provision repository secrets **JSON_DEPLOY_PRIVATE_KEY** (the restricted deployment private key) and **JSON_DEPLOY_KNOWN_HOSTS** (independently verified SSH known-hosts entry). Secret values are never stored in this profile or source files. GitHub cannot copy unreadable secret values from another repository; use the existing securely held key or a separately approved access change.

Merge the reviewed files, ensure no older deployment is running, then select this repository/workflow in Control Center's Publish update flow. Review the exact source commit before starting. After the first successful verified deployment, retire the previous central workflow and save this workflow as the website's deployment link.

## Source and deployment definitions

The required source_revision input selects the immutable source commit. Deployment scripts are checked out separately at the workflow run commit, so publishing an earlier application commit does not require that old commit to contain these scripts. Control Center reviews deployment-file versions and refuses a stale confirmation if those files change before dispatch.

deployment.json records the generation profile. To change this generated configuration, export a fresh bundle with Control Center's repository-deployment-files command and review the resulting diff; changing the profile alone does not rewrite workflow values.
